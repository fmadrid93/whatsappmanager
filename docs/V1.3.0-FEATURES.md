# WhatsApp SaaS v1.3.0-alpha

## Sesiones

Una sesión se crea con un nombre interno y un método de emparejamiento:

- **QR:** el Worker publica el QR cuando Baileys lo recibe.
- **Código:** requiere un número esperado y solicita un código de vinculación.

El número definitivo no se inventa ni se elige manualmente: se almacena después de que WhatsApp abre la conexión. El número esperado solo sirve para validar la cuenta vinculada.

Las sesiones antiguas creadas con Baileys 6 deben revincularse. Si WhatsApp devuelve 405, la sesión queda en `PAIRING_FAILED` y no entra en un reinicio infinito.

## Importación de campañas

La pantalla Campañas acepta:

- Entrada manual `Nombre,Teléfono`.
- CSV separado por coma o punto y coma.
- XLSX, primera hoja.
- API externa.

Encabezados reconocidos para el teléfono: `telefono`, `celular`, `phone`, `numero`, `whatsapp`. Todas las columnas adicionales se convierten en variables de plantilla.

## API externa

Configurar en `.env`:

```env
INTEGRATION_API_KEY=una-clave-larga-de-al-menos-24-caracteres
INTEGRATION_ADMIN_EMAIL=admin@demo.local
```

Endpoint:

```http
POST /api/integrations/campaigns
X-Integration-Key: una-clave-larga-de-al-menos-24-caracteres
Content-Type: application/json
```

{
  "idempotencyKey": "erp-cobranza-2026-07-001",

## Bot Manager

El editor v1.3 permite:

- Disparar por cualquier mensaje, coincidencia exacta o texto contenido.
- Enviar mensajes.
- Hacer preguntas y guardar la siguiente respuesta en una variable.
- Evaluar variables con `EQUALS`, `CONTAINS` o `EXISTS`.
- Enviar una respuesta verdadera o falsa.
- Finalizar y limpiar el estado del flujo.

Las variables se insertan como `{{nombre}}`. El motor conserva el paso actual por conversación, por lo que una pregunta puede continuar en el siguiente mensaje entrante.
